## Контракт реестра (`registry.mjs`)

`embeds[recId]`:
- `{ kind: 'component', load, props? }`: смонтировать компонент на месте блока, `props` передать как есть. Несколько записей с одним компонентом и одинаковыми props на странице монтировать один раз (плашка куки есть в шапке и дублируется на главной).
- `{ kind: 'global', name }`: `runGlobal(name)` из `src/lib/site-integrations.mjs`, `metrika` или `kommo`; повторные вызовы безопасны.
- `{ kind: 'skip', reason, cosmetic? }`: не переносится кодом. `cosmetic: true` значит, что правку нужно сделать в стилях (список ниже).

## Как сделано и чем отличается от живого

- **Горизонтальные прокрутки.** Как на живом: перетаскивание мышью и касание, полосы скрыты. **Колесо мыши блок не крутит и на живом сайте тоже** (функция колеса в исходнике объявлена, но не подключена). Включение: prop `wheel: true`, по умолчанию выключено, чтобы поведение совпало. Переменная `isSafari` объявлена в `util.mjs` (`detectSafari`, формула как у Тильды). Все стили и слушатели при размонтировании возвращаются.
- **Автопрокрутка `/clarity`.** Скорость и старт как на живом (2 px / 35 мс, через 1,5 с, разворот у краёв с запасом 5 px), но на `requestAnimationFrame`. Новое по поручению: касание, нажатие мыши, колесо, клавиша, фокус внутри останавливают её насовсем; наведение мыши ставит на паузу и снимает при уходе. Не крутится вне экрана, на скрытой вкладке и при `prefers-reduced-motion` (полоса остаётся прокручиваемой руками). Решение «насовсем или на время» не согласовано: если нужно возобновление через N секунд, это одна строка в `stopForever`.
- **Плашка куки.** Один в один с живым, включая неудобное: согласие даёт **любой клик** в любом месте страницы, кроме ссылки с классом `cookie-banner-link`. Ключи `cookieConsent` (`accepted`) и `cookieConsentDate` (ISO) те же. Добавлено: `try/catch` вокруг localStorage и отключение анимации при `prefers-reduced-motion`. Вёрстка `.cookieBanner` принадлежит шапке (Zero-блок), в компоненте её нет.
- **Печатная машинка.** 50 мс на букву, порог 0,5, как на живом. Текст лежит в HTML, компонент стирает и печатает; при `prefers-reduced-motion` ничего не меняется. Курсора на живом не было (класс только снимался), здесь тоже нет.
- **Снитч.** Как на живом, без искр (они были выключены) и без 12 неиспользуемых keyframes. Скрытие `opacity: 0` ставится только после монтирования компонента, поэтому без JS картинка видна. При `prefers-reduced-motion` картинка просто показана.
- **Аудиоклуб.** См. следующий раздел.

## Аудиоклуб: как это устроено

Сборка клуба (Vue + Tailwind) живёт в `~/Projects/sistema-yasnosti-club`, туда вносят месячные тексты. На сайте теперь три выпуска из локальных файлов:

```
public/embeds/audio-club/
  2026-11/club.css club.js build.json   /audio-club        (Tribute s18xT, бот ?start=audio_nov)
  2026-10/…                             /audio-club-old-old (Tribute s18xT)
  2026-09/…                             /audio-club-old    (Tribute s15wd)
  shared/assets/img|audio/…              картинки и Сати, общие для всех выпусков (одинаковые файлы не дублируются)
```

Файлы получены из снимка (`audio-club__rec5543946903/…7103`, `audio-club-old-old__…`, `audio-club-old__…`) командой `build-month.mjs` ниже, картинки и mp3 скопированы из репозитория клуба по именам из кода. Месяцы выпусков (сентябрь, октябрь, ноябрь) взяты из инвентаризации, названия папок можно переименовать, если они окажутся не такими. Единственное изменение кода выпусков: адрес `cdn.jsdelivr.net/gh/…@main/` заменён на `/embeds/audio-club/shared/`. Остальное, включая ссылки Tribute, бота и внутренние адреса `https://sistemayasnosti.com/…`, не тронуто. Проверка: в `club.css` и `club.js` нет `jsdelivr` (скрипт сам падает, если остался).

`AudioClub.vue` кладёт `#sya-club > #sya-club-app`, задаёт `window.SYA_ASSET_BASE`, подключает `club.css`, затем (после загрузки стилей, либо через 4 с) `club.js`. Бандл сам смонтируется в контейнер.

### Как обновлять страницу каждый месяц

1. В `~/Projects/sistema-yasnosti-club` обновить контент и собрать (`npm run build`, подробности в его README). Нужны `tilda/1-css.html` и `tilda/3-js.html`. Пушить в `main` для сайта больше не обязательно: картинки берутся из локальной папки.
2. Из корня этого проекта собрать новый выпуск (имя папки по месяцу):
   ```bash
   node src/embeds/audio-club/build-month.mjs --name 2026-12 \
     --css ~/Projects/sistema-yasnosti-club/tilda/1-css.html \
     --js  ~/Projects/sistema-yasnosti-club/tilda/3-js.html \
     --assets ~/Projects/sistema-yasnosti-club/assets
   ```
   Скрипт без сети и без запуска чужого кода: режет блоки, меняет базу картинок, копирует нужные файлы в `shared/assets`, пишет `build.json` (хеши и список файлов). Код выхода 1, если не хватает картинки или остался jsDelivr.
3. Новый выпуск подключить: в `registry.mjs` у блока текущей страницы заменить месяц (`clubMount('2026-12')`), а предыдущий выпуск оставить на странице «старого» (`/audio-club-old`) или удалить. Сменить в цепочке, как решит Елена: сейчас `/audio-club` = ноябрь, `old` = сентябрь, `old-old` = октябрь.
4. Ссылку оплаты Tribute и метку бота (`audio_nov` и т.п.) задаёт сборка клуба (`--bot`, текст кнопки). Проверить в `club.js` нового выпуска поиском `t.me/`.
5. Открытое: в живом снимке картинка героя `hero-player-4b2ff4db`, а в репозитории клуба лежит ещё неотслеживаемый `hero-player-becbf60e.webp`. Это, видимо, следующий выпуск; в эту сборку он не включён.

Ограничения, которые нельзя было убрать без переписывания бандла (проверка в браузере нужна):
- Бандл не умеет размонтироваться: глобальные слушатели клика по якорям остаются. Поэтому страницы аудиоклуба лучше выдавать отдельными HTML-страницами, а не переходом клиентского роутера. При уходе компонент нажимает «Пауза», если играет музыка.
- Шрифты Forum и Inter в компонент не входят (ссылки на Google Fonts из CSS-блока убраны). Нужно, чтобы общий слой сайта подключал их локально (файлы лежат в `sources/live/2026-11-09/assets/fonts.gstatic.com/`). Без них клуб отрисуется системными шрифтами.
- Предзагрузки картинок героя (`<link rel=preload>`) из CSS-блока убраны; при желании компилятор может добавить их в `<head>` страницы.
- mp3 «Гимнопедия №1» 3,3 МБ грузится только по нажатию play, как на живом.

## Список для компилятора: косметические правки Тильды (skip-блоки)

Их нужно учесть отдельно, в общих или страничных стилях.

**1. Размытие меню** (rec 1491047173 для `#nav1486554413`, rec 1488865263 для `#nav1488865513` на главной). Прозрачное меню с размытием:
```css
/* шапка */
.site-nav { backdrop-filter: blur(10px); }
@media (max-width: 960px) {
  .site-nav-mobile-container { padding: 10px 15px; min-height: 50px; height: 50px; }
  .site-nav, .site-nav-mobile { background: #F5F4F280; backdrop-filter: blur(10px); }
  .site-nav-mobile .logo img { width: 25px; height: 25px; } /* было: .tmenu-mobile_positionfixed > div > div > a > img */
}
```
Селекторы Тильды (`.tmenu-mobile…`) переписать под новую шапку. Для `backdrop-filter` добавить `-webkit-backdrop-filter`.

**2. Блик на кнопке** (rec 1491040633 на главной: `tn-elem__14865533831761599192234`; rec 2098149513 на `/about` и rec 1559325923 на `/taplink`: `tn-elem__1555825513176310873726344220`). Класс `light` вешается на кнопку jQuery-ом; взять как CSS-класс кнопки:
```css
.light { overflow: hidden; z-index: 1; position: relative; transition: 1s ease-out; }
.light:hover { box-shadow: 0 5px 20px rgba(0,0,0,.1); cursor: pointer; transition-delay: .1s; color: #fff; z-index: 8; }
.light::before { content: ""; background-color: rgba(255,255,255,.1); height: 100%; width: 3em; display: block;
  position: absolute; top: 0; left: -4.5em; transform: skewX(-45deg) translateX(0); transition: none; }
.light:hover::before { transform: skewX(-45deg) translateX(25.5em); transition: all 1s ease-in-out; }
@media (prefers-reduced-motion: reduce) { .light, .light::before, .light:hover::before { transition: none; } }
```
В исходнике в hover-правиле опечатка `webkit-transform` (без дефиса), она игнорировалась, действует `translateX(25.5em)`. `color: #fff` при наведении делает текст белым: сверить с живым.

Состояние пунктов на 09.11.2026: 2 — блик только там, где селектор находит кнопку: `/about` (класс `light` стоит в самом Zero) и `/taplink`; на главной селектор указывает на запись, которой на странице нет, блика и на живом нет. 3 — `/mini` и `/taplink` применены; на главной селектор указывает на удалённую запись, поэтому там кадр 50 % 50 %, как на живом. 4 и 5 применены в `src/style.css`.

**3. Положение кадра видео** (rec 1559313953 главная `#html-video-1486553383-176310543960410240`, rec 1713786233 `/mini` `#html-video-1703875663-1766147559512000013`, rec 1557141233 `/taplink` `#html-video-1557093663-1763043211874`): `object-position: 36% 50%` для видео.

**4. Липкий блок `/clarity`** (rec 2426973843): блок `#rec2426973823` — `position: sticky; top: 25vh; z-index: 0`. Остальное в блоке (`transform/will-change` для блоков без анимации, `#allrecords { overflow-x: clip }`, `position: relative` для блоков с фоном, сафари-обход) чинит Тильду и не переносится. Но `overflow-x: clip` у корня, возможно, нужен против горизонтальной полосы страницы от широких Zero-блоков: проверить при сверке (предположение).

Стили печатной машинки** (rec 1490588213, элемент `tn-elem__1485551813176157991652187570`, главная): `font-family: Inter; font-size: 18px; font-weight: 400; color: #4B3C25; line-height: 1.2;` на ширине до 640 px — 16 px, до 480 px — 10 px (как в живом коде; 10 px на телефоне выглядит подозрительно, сверить по эталонному скрину).

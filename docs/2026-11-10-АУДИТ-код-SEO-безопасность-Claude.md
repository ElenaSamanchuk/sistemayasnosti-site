## Находки

### Блокеры боевого запуска

**B-1. Настройка сервера превью нельзя переносить на боевой домен как есть: `X-Robots-Tag: noindex, nofollow`**
- Где: ответы `preview.sistemayasnosti.com` на каждый файл (HTML, robots.txt, sitemap.xml, картинки).
- Что не так: заголовок задан самим nginx. Сборка с `SITE_ENV=production` убирает noindex из мета-тегов, но если админ скопирует виртуальный хост превью, заголовок останется, и поисковики будут игнорировать все страницы.
- Чем мешает: сайт пропадёт из выдачи; Метрика не заметит, ошибку увидят через недели.
- Что сделать: в `deploy/ADMIN-PREVIEW.md` или в новый `deploy/NGINX-PRODUCTION.md` записать: на боевом хосте `X-Robots-Tag` не ставить; после выкладки проверить `curl -sI https://sistemayasnosti.com/about | grep -i robots` (пусто) и `curl https://sistemayasnosti.com/robots.txt` (есть `Allow: /` и `Sitemap`). Сейчас в `deploy/` боевого конфига нет совсем (есть только правила 302 для `/pred`).

**B-2. Нет сжатия и кэша для CSS, JS, JSON (на превью проверено)**
- Где: `/assets/index-*.js`, `/assets/index-*.css`, `/content/*.css`, `/content/*.json`. Проверено запросами с `Accept-Encoding: br, gzip`: HTML приходит со `Content-Encoding: gzip`, а CSS, JS и JSON приходят без сжатия; заголовков `Cache-Control` и `Expires` нет ни на одном файле (шрифты, картинки, видео, CSS).
- Цифры по боевой сборке: на главной CSS страницы 450 КБ без сжатия против 27 КБ gzip, главный JS 114 КБ против 43 КБ gzip (39 КБ brotli), шрифт Inter 48 КБ; страница `/clarity`: CSS 1028 КБ против 52 КБ gzip.
- Чем мешает: страницы на телефонах грузятся в 5-15 раз тяжелее нужного, а повторный визит перекачивает всё; на Тильде CDN отдавал сжатие и кэш. Это ухудшение относительно живого сайта.
- Что сделать на боевом nginx: `gzip on; gzip_types text/css application/javascript application/json image/svg+xml;` (brotli, если модуль есть); для `/assets/` (имена с хэшем) `Cache-Control: public, max-age=31536000, immutable`; для `/media/`, `/fonts/`, `/embeds/` хотя бы 30 дней; для HTML `no-cache` с ETag. Нужно оформить как часть инструкции админу. Тип «блокер» поставлен, потому что без этого Core Web Vitals на проде будут хуже, чем на Тильде. Если команда готова запускаться без этого, понизить до «улучшение».

**B-3. Заявки из форм не уходят (известно, решение Елены от 10.11.2026)**
- Где: все 12 страниц, компонент `src/components/ZeroForm.vue`: после проверки полей через 700 мс показывается «Данные успешно отправлены», сетевого запроса нет.
- Чем мешает: на Тильде форма отправляла данные; после переключения домена все заявки с сайта потеряются без единого сообщения.
- Что сделать: до переключения DNS подключить получателя. Это не новое открытие, а напоминание, что запуск без этого равен потере лидов. В `docs/PROGRESS.md` фиксировать, что оно открыто.

**B-4. Нет защиты от показа сайта во фрейме (регресс относительно Тильды)**
- Где: заголовки ответов. На живом сайте есть `X-Frame-Options: SAMEORIGIN`, на превью есть только `X-Content-Type-Options: nosniff`.
- Чем мешает: чужая страница может встроить форму сайта и заманить на клик (clickjacking).
- Что сделать: на боевом хосте `add_header X-Frame-Options SAMEORIGIN always;` (или `Content-Security-Policy: frame-ancestors 'self'`). Заодно `Referrer-Policy: strict-origin-when-cross-origin` и `Strict-Transport-Security` (сначала малый срок). Полную CSP не советую без отдельной проверки: нужны `mc.yandex.ru` и `gso.kommo.com` (Метрика создаёт скрипты и фреймы динамически).

**B-5. Переходы на боевом домене: http, www, слэш не описаны**
- Что проверил: на живом сайте `http://sistemayasnosti.com/about/` отвечает 200 без перенаправления на https, `www.` отдаёт тот же сайт (200), `/about/` и `/about` одинаково 200 (Тильда). На превью http уже уходит на https (301), `/about` и `/about/` оба 200 (дубль адреса, но canonical указывает на версию без слэша).
- Что сделать: в инструкции для админа записать три правила: 301 `http` → `https`; 301 `www.sistemayasnosti.com` → `sistemayasnosti.com` (в `deploy/README.md` это уже сказано, но без примера); 301 с `/about/` на `/about`. Причина про www: Метрика и Kommo в коде запускаются только при `hostname === 'sistemayasnosti.com'` (`src/lib/site-integrations.mjs`), на `www` счётчика не будет, а Тильда запускала её на любом хосте.
- Дополнительно: правила 302 для `/pred` и `/pred_fl` на живом сегодня отдают 404, на новом сайте будут вести на `/clarity`. Это решение из `DECISIONS.md` (предложение, Еленой не подтверждено): убедиться до запуска.

**U-2. Страница ставится дважды (серверная отрисовка без гидратации)**
- Где: `src/main.js` использует `createApp(...).mount('#app')`, а на сервере `createSSRApp` (`src/entry-server.js`). Vue при обычном `mount` стирает уже готовый HTML и строит страницу заново.
- Чем мешает: для поисковиков и без JS всё нормально, но в браузере блок перерисовывается сразу после загрузки, плюс страница содержит данные дважды (готовый HTML и копию в `<script id="site-page">`: на главной HTML 248 КБ, из них ~173 КБ копия). Возможная причина CLS 0,44 на аудиоклубе, отмеченного в PROGRESS. Это предположение по коду, в браузере не проверял.
- Что сделать: проверить `createSSRApp(...).mount()` (гидратация) на копии проекта; изменение в `main.js` опасное, делать только с прогоном `npm run smoke`.

**U-3. Внутренние данные лежат на публичном сервере**
- Где: `/content/*.json` (3,4 МБ), `/content/routes.json`, они нужны только для режима разработки (`App.vue`, строки около 145-152: `fetch('/content/…')` если страница не встроена). В продакшене копия уже встроена в HTML.
- Чем мешает: ничего секретного там не нашёл, но отдаётся лишний объём и служебные поля (`unsupportedNodes`, `popupsNotRendered`). Можно не выкладывать `content/*.json` на боевой сервер или закрыть, после проверки, что ничего не запрашивает их при обычной работе.
